# 05. Retrospectiva final del Sprint 3

## Qué salió bien

- Se conservó el alcance del caso de estudio simulado y se evitó usar información
  interna real del BBVA.
- El modelo de PostgreSQL quedó con relaciones y restricciones explícitas.
- La auditoría, el ciclo de vida de módulos y la regresión se transformaron en
  artefactos versionables.
- La documentación distingue evidencia real, trabajo implementado y trabajo
  pendiente.

## Qué debe mejorar

- Completar el backend REST y sus validaciones de entrada.
- Construir la interfaz responsive con mensajes de error claros.
- Integrar la auditoría con las operaciones de alta, modificación y baja lógica.
- Agregar pruebas de API y de interfaz cuando existan esas capas.

## Acciones para el próximo sprint

1. Refinar el Sprint Backlog del ABM transaccional.
2. Definir la entidad CORE y sus reglas de estado.
3. Implementar el primer flujo de alta, modificación, consulta y baja lógica.
4. Vincular cada operación con criterios de aceptación y evidencias ejecutables.
5. Actualizar el índice, el repositorio y la documentación antes de exportar la
   entrega en PDF.

## Estado de cierre

El Sprint 3 queda cerrado documentalmente con mejoras de persistencia y calidad
verificables. La aplicación completa no se considera terminada: la API, la
interfaz y la evidencia de ejecución correspondiente quedan abiertas para el
Sprint 4.
